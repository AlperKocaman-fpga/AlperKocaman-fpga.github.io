Xilinx FFT IP ile FPGA üzerinde FFTFPGA FFT with the Xilinx FFT IP

Vivado'da Xilinx FFT IP çekirdeğiyle gerçek zamanlı olmayan spektrum analizi. Bir VHDL test tezgâhı, örneklenmiş çok tonlu sinyalleri AXI-Stream üzerinden 4096 noktalı FFT'ye akıtıyor, karmaşık çıkışı ayırıyor, genliği sabit noktalı Newton-Raphson karekökle hesaplıyor ve sonuçları dosyaya yazıyor. Spektrumlar MATLAB'a karşı doğrulandı.

Non-real-time spectrum analysis with the Xilinx FFT IP core in Vivado. A VHDL testbench streams sampled multi-tone signals into a 4096-point FFT over AXI-Stream, splits the complex output, computes the magnitude with a fixed-point Newton-Raphson square root, and writes the results to files. The spectra are verified against MATLAB.

ÇalıştırmaRunning it

  1. Test sinyalini üretGenerate a test signal

    Satır başına bir 32-bit ikili örnek: [15:0] reel, [31:16] sanal.

    One 32-bit binary sample per line: [15:0] real, [31:16] imaginary.

    python scripts/gen_stimulus.py --tones 5e6 10e6 15e6 -o input_samples.txt

  2. Vivado projesini kurSet up the Vivado project

    xfft_0'ı yukarıdaki ayarlarla üret, sim/tb_fft.vhd'yi simülasyon tepesi yap ve input_samples.txt'yi Simulation Sources'a ekle; Vivado dosyayı xsim çalışma dizinine kopyalar.

    Generate xfft_0 with the settings above, add sim/tb_fft.vhd as the simulation top, and add input_samples.txt to Simulation Sources so Vivado copies it into the xsim run directory.

  3. Davranışsal simülasyonu çalıştırRun behavioural simulation

    Test tezgâhı fft_data_out.txt ve degerler.txt dosyalarını xsim dizinine yazar (<proje>.sim/sim_1/behav/xsim).

    The testbench writes fft_data_out.txt and degerler.txt into the xsim directory (<project>.sim/sim_1/behav/xsim).

  4. Spektrumu çiz ve karekökü kontrol etPlot the spectrum and check the square root

    python scripts/plot_spectrum.py --sim-dir <project>.sim/sim_1/behav/xsim --fmax 25e6

Bilinen sınırlar ve sonraki adımlarKnown limitations and next steps

  • Genlik test tezgâhında. FFT, IP çekirdeğinin kendisi; genlik ve karekök ise test tezgâhında (yalnızca simülasyonda) hesaplanıyor. Donanım sürümünde bunlar CORDIC ya da pipeline karekök kullanan bir modüle taşınır.
  • Newton-Raphson aralığı. Fonksiyon ≈ |X|·2¹⁵ döndürüyor ve başlangıç tahmini girdi/4 olduğu için 8 iterasyonda (< %0,1 hata) yalnızca |X|² ≈ 2²²–2⁴⁶ aralığında yakınsıyor. Tam ölçekli 16-bit bir tonun ölçeksiz 4096 noktalı FFT'si yaklaşık 2⁴⁹'a ulaşıyor ve tepelerde ~%13'e varan hata veriyor. İterasyonu en anlamlı birin konumundan (≈ 2^(msb/2)) başlatmak bunu çözer.
  • Çerçeve kontrolü. s_axis_data_tlast yalnızca giriş dosyası bitince kalkıyor ve çıkış döngüsü hiç bitmiyor. Her 4096 örneklik çerçevenin son örneğinde tlast vermek ve son çıkış çerçevesinden sonra durmak test tezgâhını kendiliğinden sonlanır hale getirir.
  • Spektrum merkezleme. Çıkışa FFT shift uygulamak iki taraflı spektrumu okumayı kolaylaştırır.
  • Magnitude in the testbench. The FFT is the IP core; magnitude and square root are computed in the testbench (simulation only). A hardware version would move them into a pipelined module using a CORDIC or a pipelined square root.
  • Newton-Raphson range. The function returns ≈ |X|·2¹⁵ and converges within 8 iterations (< 0.1 % error) only for |X|² of roughly 2²² to 2⁴⁶, because the initial guess is input/4. An unscaled 4096-point FFT of a full-scale 16-bit tone reaches about 2⁴⁹, which gives up to ~13 % error at the peaks. Seeding the iteration from the position of the leading one (≈ 2^(msb/2)) fixes this.
  • Frame control. s_axis_data_tlast is raised only after the input file ends, and the output loop never exits. Asserting tlast on the last sample of each 4096-sample frame and stopping after the last output frame would make the testbench self-terminating.
  • Spectrum centring. Applying an FFT shift to the output would make the two-sided spectrum easier to read.
